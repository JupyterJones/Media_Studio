Here's how models are located and how the dynamic `MODELS_ROOTS` system works in Media Studio:
### Where Models are Located
Models are expected to be found within specific subdirectories (e.g., `checkpoints`, `loras`, `vae`) under a list of predefined root directories specified by `MODELS_ROOTS`.
The `ONE_model_seeds.py` script defines the following potential root directories:
1.  **`/media/jack/9930-14E1/models`**: A path likely pointing to an external hard drive or partition.
2.  **`/media/jack/USB_USBSSD/models`**: A path for a USB SSD or similar external storage.
3.  **`[BASE_DIR]/models`**: A local `models` directory relative to the script's location (e.g., `~/MediaStudio/models`).
4.  **`~/Desktop/Comfy-UI/models`**: A path to a `models` directory typically used by ComfyUI, located on the user's desktop.
Within these `MODELS_ROOTS`, the system specifically looks for:
*   **Checkpoints (Stable Diffusion models):** In `checkpoints/` subdirectories (e.g., `/media/jack/9930-14E1/models/checkpoints`).
*   **LoRAs:** In `loras/` subdirectories (e.g., `/media/jack/USB_USBSSD/models/loras`).
*   **VAEs:** In `vae/` subdirectories (e.g., `~/MediaStudio/models/vae`).
### How Dynamic `MODELS_ROOTS` Works
The `MODELS_ROOTS` list provides a flexible and dynamic way to locate various types of generative AI models across different storage locations.
Here's a breakdown of its mechanism:
1.  **Centralized Root Definitions:**
    *   `MODELS_ROOTS` is a list of *parent* directories where model subfolders might reside. This allows Jack to keep models on different drives or in different organizational structures (e.g., dedicated external drives, local project folders, or shared folders with other tools like ComfyUI).
    ```python
    MODELS_ROOTS = [
        "/media/jack/9930-14E1/models",
        "/media/jack/USB_USBSSD/models",
        os.path.join(BASE_DIR, "models"),
        os.path.join(os.path.expanduser("~"), "Desktop", "Comfy-UI", "models"),
    ]
    ```
2.  **Derivation of Specific Model Type Directories:**
    *   From `MODELS_ROOTS`, specific lists for `CHECKPOINTS_DIRS`, `LORAS_DIRS`, and `VAE_DIRS` are generated by appending the respective subdirectory names. This means the system will search for a checkpoint model in *each* `checkpoints` folder found under *each* root path in `MODELS_ROOTS`.
    ```python
    CHECKPOINTS_DIRS = [os.path.join(r, "checkpoints") for r in MODELS_ROOTS]
    LORAS_DIRS = [os.path.join(r, "loras") for r in MODELS_ROOTS]
    VAE_DIRS = [os.path.join(r, "vae") for r in MODELS_ROOTS]
    ```
    *   For instance, `CHECKPOINTS_DIRS` would become a list like:
        *   `/media/jack/9930-14E1/models/checkpoints`
        *   `/media/jack/USB_USBSSD/models/checkpoints`
        *   `[BASE_DIR]/models/checkpoints`
        *   `~/Desktop/Comfy-UI/models/checkpoints`
3.  **Prioritized Searching and Resolution:**
    *   When the script needs to find a specific model (e.g., through `resolve_model()`, `resolve_lora()`, `resolve_vae()`), it iterates through these derived directory lists (`CHECKPOINTS_DIRS`, `LORAS_DIRS`, etc.) in the order they are defined.
    *   The first existing file that matches the model name (or a partial match/index) in any of these directories is returned. This gives a natural priority to models on certain drives or in specific locations (e.g., external drives are checked before the local `BASE_DIR` or ComfyUI directory).
    *   The `get_available_models()` function also uses this approach to build a comprehensive list of all discovered checkpoint models across all configured paths.
This dynamic approach ensures that Media Studio can locate models efficiently, even if Jack moves them between different external drives or has them organized in various system locations, without needing to hardcode absolute paths for individual models.
